## 字阶层 · 三声部（提交 `6b32f98`）

**用户原话**：给了一张参考图（斜体黑衬线写 `pick it, wait for it, keep the joy.`）+
「这个英文字体比较好看 就是字体不能所有的都一样，需要有些突出之类的」。

**判断**：不是字体的问题，是**声部**的问题。09-17 那版把全站收敛进五支角色字体做对了，
但顺手把层级也压平了 —— 51 处 `var(--f-serif)` 里 45 处都是 `w500`，中文大标题也全是 500，
「大标题」和「小标签」只差字号。实测印证：首页 115 个可见文字块里 Fraunces 只占 5 个，
PingFang 400/500 占 72 个，整页一条直线。

**做法**：不引新字体，只在同一支 Fraunces 之内开三档。
- ① 重音 display：斜体 **800** + `font-variation-settings:"SOFT" 0,"WONK" 1`
  → 只有 4 处落点：`.brand`（Soft Life 店招）· `.section-title` · `.product-section h1` · `.ending-aside`
- ② 标题 headline：正体 500 → 600（价格与大数字：bottom-price / cart-price / archive-bar span /
  pet-stat-num / ledger-stat b / rescue-tally b / charity-hero-num）
- ③ 中文大标题：500 → 600（中文落宋体 → Songti Bold；hero / store-head / ending-title / world-hero …）
- `.section-title em`（计数字）显式退回 upright 500 —— 一行之内造落差，否则 em 继承 800 等于白加。
- `@import` 改成变量区间 `ital,opsz,wght@0,9..144,400..900;1,9..144,400..900`
  （原来 `1,9..144,500` 只给斜体 500 → 800 会是伪斜体）。
- `opsz` 不写死，交给 font-optical-sizing 跟字号走。

**顺带两件**：
- 结局页 `that's the soft life` 从 `ending.body` 里拆出来独立成行（新 `.ending-aside`，19px），
  它是小铺的「声音」，之前混在 13.5px 正文里 —— 最该响的一句反而最轻。
- `text-wrap: balance` 治孤字行：结局标题「今天你把自己照顾得很好」11 字 ×28px = 308px，
  卡片内宽 292px → 原本断成 10+1，最后那个「好」孤零零占一行；均衡断行切成 6+5。

**清掉 25 处跑掉的旧字体**（`tools/migrate-stray-fonts.py`，按选择器逐个路由，不 replace-all）：
Quicksand / Nunito / Cormorant Garamond 还在文件里，**其中 8 处是带反斜杠的**
（`\"Quicksand\"`）—— CSS 里那是「标识符里的引号字符」，跟字体名不等价 → 整条 font 声明
静默回退到 system-ui / 通用 serif。DishArt 的 SVG 里 3 处 Nunito 也换成 Space Mono。

### ① 切页进场：两条路试过都被否掉

**第一版走 View Transitions**（理由很充分：给页面套 transform 会让 `position:fixed` 的
`.bottom-bar` 换包含块，VT 拍整张视口快照天然没这问题；`flushSync` 包住 setState）。
视觉上完全成立，伪元素动画名也确认拿到了 `vtInFwd`/`vtOutFwd`、方向选择器生效。

**但 `verify-pet-pat` 红了**：`(195,122.9) 应该落在按钮上`。查下去是真缺陷 ——
**Chrome 在转场进行中不让实时内容参与命中测试**：

| 探法 | 转场中 | 转场结束 |
|---|---|---|
| `elementFromPoint` | 一律 `HTML` | `IMG`（按钮内）|
| 真实鼠标点顶栏返回键 | **回不去**（连点两次都停在「全部店铺」）| 正常 |
| `::view-transition{pointer-events:none !important}` | computed 确认是 `none`，**照样拦** | — |

也就是**每次切页有 ~260ms 全页点不动**。对一个"用手点"的 App 不可接受 → 整个方案砍掉。

顺带否掉的第一条路（本来就知道）：「给页面套 transform 做滑入」会把 `.bottom-bar` 的
包含块从视口换成那个祖先，动画期间底栏被钉到内容底部。两条路都写进 main.jsx 注释了。

**最终方案**：给屏幕根节点的**子元素**加 `opacity + translate` 进场（前进从右 10px、
返回从左，方向在 `<html data-nav>`），`.bottom-bar` 用 `:not()` 排除（它在视口底部固定，
本来就该纹丝不动、立刻可用）。守住两条：只动子元素（动根节点会换掉内部 fixed 的包含块）；
**填充用 `backwards` 不用 `both`** —— `to` 里不写 translate 时 Chrome 解成 `translate: 0px`，
而 `0px` ≠ `none`，`both` 会让这些元素永久挂包含块，把 `.jh-detail`/`.modal-backdrop`/
`.exchange-backdrop` 全弄坏（这条是断言量出来的，不是想出来的）。

### ② 全局点击手感

原来全站只有 8 处写 `:active`（`.add-button`/`.primary-button`/…），chip / 磁贴 / 图标按钮
按下去毫无反应 —— 这就是"缺交互"的主要来源。新增一层：
`button:not(:disabled)` 统一 transition（权重 (0,1,1) 压得住各页类规则）+ `:active` 时长压到 .07s、
松开走 `cubic-bezier(.34,1.56,.64,1)` 回弹；幅度分组 小图标 .86 / chip .93 / 大块面 .994 / 兜底 .97；
**用独立的 `scale`/`translate` 属性，不用 `transform`**（和既有 transform 相乘，不会互相覆盖 ——
本项目踩过两个 transform 只有一个生效）；`.flip-toggle`（翻面卡）排除，会和 3D 翻面打架。
另加统一 `:focus-visible` 焦点环 + `-webkit-tap-highlight-color: transparent` + `touch-action: manipulation`。

**真踩到的坑**：兜底写的 `button:active:not(:disabled):not(.flip-toggle)` 权重 (0,3,1)，
比分组写的 `.icon-button:active:not(:disabled)` (0,3,0) **还高** → 所有分组幅度全部失效、
全站一律 0.97。肉眼完全看不出来（0.97 也在动），是 `verify-interactions` 用
`CSS.forcePseudoState` 量出来的。改成 `:not(:where(...))` 归零权重才对。
