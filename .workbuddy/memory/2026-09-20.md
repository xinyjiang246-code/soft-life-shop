## 体检发现（都是「给别人用才会暴露」的那种）

1. **iPhone 底部安全区没做** —— `.bottom-bar` 是 `position:fixed; bottom:0; padding-bottom:24px`，没有 `env(safe-area-inset-bottom)`；而且 `index.html` 的 viewport 没写 `viewport-fit=cover`（不写的话 `env()` 恒为 0，所以两处得一起改）。真机停在 home indicator 上。
2. **`100vh` 两处**（`.page-shell` / `.shop-page` 的 `min-height`）→ iOS Safari 上 `100vh` 含浏览器 chrome 高度，会多出一截假滚动。改 `100dvh`（保留 `100vh` 作兜底）。
3. **没有 favicon / apple-touch-icon，也没有 `public/` 目录** —— 「添加到主屏幕」会是个默认字母图标；分享出去的链接也没有图标。
4. **仓库里挂着一个 gitlink**：`soft-life-app/`（9-06 的 Expo 脚手架残骸，自带 `.git`）被记成 `160000` 条目且没有 `.gitmodules` → 推到 GitHub 会变成一个打不开的空文件夹，clone 下来也是空的。必须 `git rm --cached` + 进 `.gitignore`（或删掉整个文件夹）。

## 仓库卫生（公开前必须处理）

- 已跟踪但**不该公开**的：`references/`（50MB / 17 张「我的参考」是网上存的别人的图，含品牌物料）· `预览截图/`（61 张）· `.workbuddy/memory/*.md`（私人工作记录）。

- `package.json` 里依赖全是 `"latest"`（react / vite / lucide-react / @vitejs/plugin-react）—— 别人 clone 下来哪天就装不上。**开源前应钉版本号**。
- 目前 `git remote` 为空，还没有远端仓库。

## 路线结论

GitHub 和小红书**不是二选一，是上下游**：小红书是「人从哪来」，GitHub 是「代码放哪」。两者都卡在同一件事上 —— **没有手机能打开的网址**（现在只能本地 `http.server` 开在 dist/）。所以第一步不是选平台，是先拿到一个 https 链接。

- 只想让人玩 → 云托管（Vercel / Cloudflare Pages，免费、https、**仓库可私有**）。
- 想顺带当作品集 / 开源 → GitHub 公开 + Pages（免费版 Pages 要求公开仓库）。
- 不建议先开源再找人：先让作品以「人」的形式出现（小红书），再决定要不要开源。
- 小红书注意：正文不能放外链（限流），惯例走评论区 / 私信 / 主页；「公益 / 捐款」字眼敏感 —— 但本项目的红线恰好是「绝不暗示我们替你捐了」，天然安全。
