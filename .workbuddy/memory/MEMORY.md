# 慢活小铺 · 项目长期约定

> 只留「下一个人接着做必须知道」的决策与红线。**操作细节一律见 skill `soft-life-web-dev`**，用户原话见各日 `YYYY-MM-DD.md`。

## 一、这是什么 / 为什么做

**核心初衷（用户原话）**：不饿、减肥、已经吃撑的时候，仍想点一次外卖 —— 想花掉那笔钱、**完成下单的仪式**；但食物不该被真消耗（不浪费粮食），钱该流向公益（捐猫粮，按克计）。

**结构 = 真正的外卖 App**（不是商场扫码点餐）：`home` → `counter` → `cart` → `checkout` → `delivery` → `ending` →（捐猫粮）→ `charity` 档案。两条独立入口走同一条主流程：`world`（AI 世界菜单）· `rescue`（惜食柜）。店铺返回用 `from` 参数，`goBack` 据此分发。

**6 家店**：`tea` 慢活茶饮铺 · `bento` 暖食便当柜 · `dessert` 怀旧甜点柜 · `life` 慢活选物 · `noodle` 深夜面馆·十二点后 · `dimsum` 一盅两件

**定位升级（2026-09-16 晚，用户原话）**：「我现在希望之后是一个开放的产品 就是大家都可以用」→ 按**面向陌生人**做。连带作废：给 AI 起私名（「小满」提案撤回）—— 开放产品里"我"应该是**小铺统一的声音**，不是每个用户各自起名的私人助手。全站也没有「怎么称呼你」这种字段（唯一能填名字的是结算页「虚拟小屋名称」）。

**✅ 2026-09-16 晚已定档：走「一个人的仪式」这条路，不用后端。** 用户原话：「第一个哦，公益的话我觉得也可以呀 就是把用在外卖等乱七八糟的地方给小猫咪」。→ 产品模型 = **钱是真的，转账那一步由用户自己走**；App 只做两件事：把「本来要花掉、现在没花」**换算成看得见的克数** + **记账**。因此不需要账号 / 服务器 / 数据库，每个人自己装一份即可。**红线：绝不能暗示"我们已经替你捐了"**（现有文案「元折算出去」偏暗示，待改）；另需一个「我真去捐了」的闭环出口（自查/盖章），否则账永远只是数字。

## 二、菜品与商品图

三层供给：① 招牌 13 款（draw + real 两张真图，可翻面）② 新菜 8 道面点（`assets/dishes/*.webp`，仅实拍）③ 世界层 `dishForge.js`（10 城，每天换）+ 自建层 `MyShopScreen`。

## 三、公益 · 慢活猫粮计划

`data.js` 末尾 `CHARITY`：`gramsPerYuan:10` / `gramPerCatDay:60` / `defaultRatio:30` / `presets:[10,30,50,100]`；持久化 `soft-life-charity-v1`。
**规模红线**：用户原话「比例不能太多！因为我们现在比较小」→ 默认 30%，不鼓励全捐。档案页必须诚实：「这个 App 没有后端…它是一本账，不是一次真实的转账」。

## 四、配送等待页 · 慢活额度（核心机制）

用户原话：「加速没有任何互动就直接点就可以了…太无聊了」+「**如果没有任何代价的话，这个 app 是运行不下去的**」。**前提：时间是这个小铺里唯一真实的资源** → 给时间定价，**不加小活动**。

- **慢活额度** `soft-life-patience-v1`：每天 10 分钟，快进按 `ceil(剩余秒/60)` 扣，跨天回满；不够则按钮禁用
- **加速 = 催单仪式**（三选一问候 → 骑手回话 → 进结局），**永远不要退回「一键跳过」**；**等满不扣额度**，还多掉一枚贴纸
- 等待页四件套：骑手来信（按进度显示 `04/07`）· 软软陪等 · 现实小事（可勾选）· 额度面板
- ⚠️ **「不做小游戏」**：劝人慢下来少看屏幕的 App 加消磨时间的游戏自相矛盾。2026-09-16 用户裁决：`RiderGame`（骑手小跑酷）→ **改造后保留**，即现在的 `RiderWindow`（见第八节）

## 六、虚拟伙伴「软软」与邻居猫

- **形象 = 猫**（2026-09-14 敲定，兔熊时代结束**别再退回**）：**软软**（5 阶段成长）+ **邻居猫**（不成长，每天串门）；氛围词一律用「**小饼干**」，**不要写「猫粮」**
- **点它要有身体反应（2026-09-16，用户原话「这个小猫你点它的时候我不是说过它身体上之类的等等要有反应吗」）**：`src/petTouch.js` + `components/PetPops.jsx`。**形象是平面水彩图，图里的耳朵尾巴动不了 → 只能靠「形变」表达**（挤压拉伸 / 歪头 / 发抖 / 蹭）：六部位六种反应 + 1.5 秒内连击放大 + 指尖小图（SVG，禁 emoji）。**三层必须分开挂**：`.pet-idle` 呼吸 / `.pet-hit` 反应（WAAPI）/ 底下的图 —— **同一元素上两个 transform 动画会互相覆盖**。细节与坑见 skill
- 素材 `assets/pets/a-cream-stage{0-4}.webp` + `neighbor.webp`（220:248）；`SoftPet.jsx` **图片优先、SVG 兜底**（那个 SVG 是兔熊旧版，**别再投入**）；**毛色选择器已退役**，`loadPet()` 把旧存档归一到 `cream`
- ⚠️ **两条独立取图出口**：`.pet-photo`（软软）与 `.neighbor-cat`（邻居猫）。取图一律「**用 glob 的 key 去取 value**」—— 直接拿 key 当 `<img src>` 会 404。**改一条要回头验收另一条**
- 出图链：原图丢 `宠物生图原始/{新形象,邻居猫}/` → `python3 tools/petForge.py`；`petForge.py` 出带米色方底版 → `tools/petKnockout.py` 再出**真透明底** `*-t.webp`，`petArtUrl()` 优先择透明版。**跑完 petForge 必须顺手跑 petKnockout**；透明底自动合成米色（**别退回 `convert("RGB")`**，会把透明压成黑块）
- **表情层（2026-09-17，用户：「表情也可以变呀」）**：扁平图五官动不了 → 走「**换底图 + 重画五官**」。`tools/petFace.py` 量锚点（**不能腐蚀去噪**，眼睛是环形带高光会被整只吃掉）+ 出**无眼底图** `assets/pets/noeye/*-t.webp`（**必须用 `MaxFilter` 形态学膨胀**，扩散填充会把眼睛周围灰水彩晕抹进来）。锚点落在自动生成的 `src/petFace.js`，**别手改**；表情在 `components/PetFace.jsx`。
  **七个表情**：耳=`squint` / 头=`bliss` / 脸=`smile`（左右要镜像）/ 肚=`purr` / 爪=`startle`（**白眼球放大+瞳孔缩小**，不是放大黑眼）/ 连点 3 下=`heart` / 5 下=`star`；`FACE_HOLD=1150ms` 自己收回。
  ⚠️ **只有宠物页传 `faces={true}`** —— 首页 58px 溜达猫开了会白下 25KB 图、且 `.pet-noeye` **把点击吃掉**（首页摸猫失效）。
- **`nose` 不是 `mouth`，且软软本来没有嘴（2026-09-17 补的第二刀）**：量到的那个点是**鼻子**（放大 7 倍确认鼻子下面是水彩纸纹）。**嘴全靠 `PetFace.jsx` 画**，位置从 nose 推（`nose.y + ry*0.85`，跟 tilt 转）。
  踩过的三条：① 嘴的纵向尺寸**只能跟眼睛挂钩**（第一版按眼距算，`flat` 只有 3 个 viewBox 单位高 ≈ 亚像素，等于没画）② **二次贝塞尔顶点只有控制点的一半**（想要 `dip` 就得写 `dip*2`）③ **ω 嘴两段都要走满 w**（第二段只写 `w/1.5` 会让嘴整体偏左 1/3 宽）。
  **嘴那层必须包两层 `<g>`**：外层放 SVG `transform` 属性、内层 `.pf-mouth` 留给 CSS 动画 —— **CSS transform 会盖掉 SVG 的 transform 属性**。

## 七、惜食柜 · 打折区

**立意（用户原话）**：「这东西在商店里放很久了，别人不要的，我买下来就不算浪费粮食」+「每段时间出一些这种打折菜单」→ 定位 = **「关门前剩下的几份」，不是促销**。这条决定后面所有文案与配色。

**语气红线**：**不要红色、不要倒计时、不要「仅剩 N 件」、不要「限时秒杀」**。视觉走木色 + 亚麻 + 一点黄油色。
**账本主角是「份数」**：`份被留下`（主格高亮）+ `单带走它们` + `¥ 比原价少花`（第三位、弱化）；落点是「这份饭被你留下了」，不是「你少花了钱」。

**规则**：每天 3 件、折率 30/40/50%（**三件折率必须互不相同**，各自独立哈希会三件全撞 -50%，像全场大促）· **每件 2 份**（`RESCUE.perItem`；拦截在 `addToCart` 层，购物袋「+」同步禁用）· 折价品**独立 id**（`rescue-` 前缀 + `originalId`），**原商品价格绝不改写** · 只从**食物类**柜台挑 · 生成**确定性**（种子只来自 `dateSeed()`）· **记账时机在结局页**（与宠物成长、公益捐赠同一节拍）

持久化 `soft-life-rescue-v1`；UI = 首页 `.rescue-strip` → `RescueScreen` → 购物袋原价划掉 → 结局 `.rescue-recap`。
**验证关键**：结算合计走**折后价**（三件 ¥26/¥22/¥42 → ¥13/¥15/¥25，合计 ¥53 而非 ¥90）。

## 九、技术 / 验证约定

**操作细节全部见 skill `soft-life-web-dev`（含 63 条坑点）。这里只留最贵的：**

- 预览：`python3 -m http.server 8080 --bind 127.0.0.1`（**cwd 必须是 `dist/`**）→ http://127.0.0.1:8080/；**别让用户直接开 `file://` 的 dist/index.html**（白屏）。`vite.config.js` 的 `base: './'` 不能动
- **购物袋金额只有一处实现**：`data.js` 的 `cartBreakdown(cart)`。**新增用到金额的页面一律调它**
- **角标必须与真实内容一致**：`main.jsx` 有一条对账 effect（依赖 `[worldItems, rescueShelf, cart, wishes]`），如实清出查不到的条目并 toast。**新增任何「每日会变」的商品来源都要挂到它后面**
- ⚠️ **「build 绿」≠「接线对」**：esbuild 不查作用域，`onXxx={从未定义的函数}` 照样构建成功，只在进到那个页面时才炸（出过两次）。**加/改回调 prop 后一定 grep 一遍定义**，并**真机走到那个页面**验一次
- ⚠️ **假警报比漏报更贵**（懒加载没触发 / `onBlur` 没触发 / BSD `grep` 失配，各骗过一次）。**纪律：断言失败先怀疑探针，用第二种独立手段复核，最后才改产品代码**
- ⚠️ **截图或量几何前必须等动画播完**（`getBoundingClientRect` 返回的是**变换之后**的矩形）；**别用 `getAnimations().map(a => a.finished)`** —— 无限循环动画（乱走的猫 / 雨丝）永不 resolve。用 `scripts/shot-page.mjs`
- ⚠️ **`captureScreenshot` 的 `clip` 是页面坐标**，滚动过就得加 `scrollX/scrollY`；**注入 `Runtime.evaluate` 的字符串里的正则转义会被 Node 先吃一遍**（`/\\s+/` → `/s+/`），**反引号模板也不能嵌套**（会被提前闭合）。改完 `.mjs` 先 `node --check`
- ⚠️ **探针要用明确类名定位，别按结构猜**（给表情层加嘴时，「找眼睛」的 `g[transform]` 把嘴也抓进去了 → 报 TypeError，像产品坏了其实是探针太宽松）；**断言先比数量再算偏差**
- ⚠️ **「状态写了但没人渲染」要按数据问题查**（`ArchiveScreen` 的 `archives` 写了两天没人读 —— 上传的照片没有出口）。查法只问两句：**它从哪进来？在哪里被读出去？**
- ⚠️ **`waitFor` 的条件要选「只有成功才会出现」的东西** —— 包含「点下去立刻出现」的提示文案就是**假绿灯**（`.archive-hint` 骗过一次，断言全红像产品丢数据）
