# 慢活小铺 · 项目长期约定

> 只留「下一个人接着做必须知道」的决策与红线。**操作细节一律见 skill `soft-life-web-dev`**，用户原话见各日 `YYYY-MM-DD.md`。

## 一、这是什么 / 为什么做

**核心初衷（用户原话）**：不饿、减肥、已经吃撑的时候，仍想点一次外卖 —— 想花掉那笔钱、**完成下单的仪式**；但食物不该被真消耗（不浪费粮食），钱该流向公益（捐猫粮，按克计）。

**结构 = 真正的外卖 App**（不是商场扫码点餐小程序）：`home` → `counter`（进店才看菜单）→ `cart` → `checkout` → `delivery` → `ending` →（捐猫粮）→ `charity` 档案。
两条独立入口走同一条主流程：`world`（AI 世界菜单）· `rescue`（惜食柜）。店铺返回用 `from` 参数，`main.jsx` 的 `goBack` 据此分发。

**6 家店**：`tea` 慢活茶饮铺 · `bento` 暖食便当柜 · `dessert` 怀旧甜点柜 · `life` 慢活选物 · `noodle` 深夜面馆·十二点后 · `dimsum` 一盅两件

## 二、菜品与商品图

三层供给：① 招牌 13 款（draw + real 两张真图，可翻面）② 新菜 8 道面点（`assets/dishes/*.webp`，仅实拍）③ 世界层 `dishForge.js`（10 城，每天换）+ 自建层 `MyShopScreen`。

- 生成**必须确定性**：种子只来自 `(城市, 批次, 日期)`，**绝不用 `Date.now()`**，否则购物车里的商品刷新后查不到
- 世界菜单 / 惜食柜商品**不进** `getAllItems()`，只加进 `getItem()` 一层查找
- **商品图一律走 `ItemArt.jsx`**：`prefer="real"`（店铺 / 购物袋 / hero）· `prefer="draw"`（我的小店 / 手账）；无图用 `DishArt.jsx` 蜡笔 SVG，**禁止退回 emoji**
- 每款**两张独立图**（不是上下拼接），点图翻面由 `FlipImage.jsx` 实现（角标已改为随正反面走）；一律 WebP（draw q82 / real q80）；**禁止 1MB 级 PNG 进 dist**（白屏）
- ⚠️ 部分 draw 原图自带「灰墙 + 白画框」装裱构图（`matcha-latte` / `journal` / `nourish-bowl` 已裁成画芯，备份 `products_old/*.framed.webp`）；实拍图残留的 AI 装饰文字要裁掉，draw 版的设计文字保留

## 三、公益 · 慢活猫粮计划

`data.js` 末尾 `CHARITY`：`gramsPerYuan:10` / `gramPerCatDay:60` / `defaultRatio:30` / `presets:[10,30,50,100]`；持久化 `soft-life-charity-v1`；`CharityScreen` 是完整档案页。
**规模红线**：用户原话「比例不能太多！因为我们现在比较小」→ 默认 30%，不鼓励全捐。
档案页必须诚实：「这个 App 没有后端…它是一本账，不是一次真实的转账 —— 但我们按真实的方式记账」。

## 四、配送等待页 · 慢活额度（核心机制）

用户原话：「加速没有任何互动就直接点就可以了…太无聊了」+「**如果没有任何代价的话，这个 app 是运行不下去的**」。
**前提：时间是这个小铺里唯一真实的资源** → 给时间定价，**不加小活动**。

- **慢活额度** `soft-life-patience-v1`：每天 10 分钟，快进按 `ceil(剩余秒/60)` 扣，跨天回满；不够则按钮禁用
- **加速 = 催单仪式**（三选一问候 → 骑手回话 → 进结局），**永远不要退回「一键跳过」**
- **等满不扣额度**，还多掉一枚贴纸（正向激励等下去）
- 等待页四件套：骑手来信（按进度显示 `04/07`）· 软软陪等 · 现实小事（可勾选）· 额度面板
- ⚠️ **「不做小游戏」**：劝人慢下来少看屏幕的 App 加消磨时间的游戏是自相矛盾；要做就做「离开屏幕」的反向活动。
  2026-09-16 用户裁决：`RiderGame`（骑手小跑酷）→ **改造后保留**，即现在的 `RiderWindow`（见第八节）

## 七、惜食柜 · 打折区

**立意（用户原话）**：「这东西在商店里放很久了，别人不要的，我买下来就不算浪费粮食」+「每段时间出一些这种打折菜单」→ 定位 = **「关门前剩下的几份」，不是促销**。这条决定后面所有文案与配色。

**语气红线**：**不要红色、不要倒计时、不要「仅剩 N 件」、不要「限时秒杀」**（电商语言）。视觉走木色 + 亚麻 + 一点黄油色。
**账本主角是「份数」**：`份被留下`（主格高亮）+ `单带走它们` + `¥ 比原价少花`（第三位、弱化）；落点是「这份饭被你留下了」，不是「你少花了钱」。

**规则**：每天 3 件、折率 30/40/50%（**三件折率必须互不相同**，各自独立哈希会三件全撞 -50%，像全场大促）· **每件 2 份**（`RESCUE.perItem`；拦截在 `addToCart` 层，购物袋「+」同步禁用）· 折价品**独立 id**（`rescue-` 前缀 + `originalId`），**原商品价格绝不改写** · 只从**食物类**柜台挑 · 生成**确定性**（种子只来自 `dateSeed()`）· **记账时机在结局页**（与宠物成长、公益捐赠同一节拍）

持久化 `soft-life-rescue-v1`；UI = 首页 `.rescue-strip` → `RescueScreen` → 购物袋原价划掉 → 结局 `.rescue-recap`。
**验证关键**：结算合计走**折后价**（三件 ¥26/¥22/¥42 → ¥13/¥15/¥25，合计 ¥53 而非 ¥90）。

## 九、技术 / 验证约定

**验证与截图的操作细节全部见 skill `soft-life-web-dev`（含 46 条坑点）。这里只留最贵的几条：**

- 预览：`python3 -m http.server 8080 --bind 127.0.0.1`（**cwd 必须是 `dist/`**）→ http://127.0.0.1:8080/；**别让用户直接开 `file://` 的 dist/index.html**（白屏）。`vite.config.js` 的 `base: './'` 不能动
- **购物袋金额只有一处实现**：`data.js` 的 `cartBreakdown(cart)`。**新增用到金额的页面一律调它**
- **角标必须与真实内容一致**：`main.jsx` 有一条对账 effect（依赖 `[worldItems, rescueShelf, cart, wishes]`），如实清出查不到的条目并 toast。**新增任何「每日会变」的商品来源都要挂到这条 effect 后面**
- ⚠️ **「build 绿」不等于「接线对」**：esbuild 不查作用域，`onXxx={someCallback}` 里引用**从未定义**的函数照样构建成功，只在进到那个页面时才炸（出过两次）。**加/改回调 prop 后一定 grep 一遍定义**，并**真机走到那个页面**验一次
- ⚠️ **网络中断可能只丢「半个文件」**：曾出现 JSX 落了盘、import 和 state 没落盘 → 标识符全 undefined。**别因为「文件里有新代码」就判定改动完整**，要逐个标识符核对
- ⚠️ **假警报比漏报更贵**（一天连吃三个）：`naturalWidth 0`（其实是懒加载没触发）、便签没存（其实是 `onBlur` 没触发）、文件没改（其实是 BSD `grep` 的 `\|` 失配）。**纪律：断言失败先怀疑探针，用第二种独立手段复核，最后才改产品代码**
- 搜中文多关键词**一律用 `Grep` 工具**（bash `grep` 的 `\|` 在 macOS BSD grep 下常静默失配）
- **`SoftPet.jsx` 的 Edit 会静默失败，而且 `Grep` 对它失灵**：改完必须用 python 复核关键字符串
- CSS：`.flip-frame` 必须 `position:relative`；**数字字形 `lining-nums` 汇总规则必须留在文件最末**（压缩器会把 `font:` 简写挪后、从而重置它）；**大段新增务必 grep 一次**避免重复写入

## 十、并行开发 · 规模 · 版本保护

- ✅ **2026-09-16 已建 git 基线**（`git init` + `.gitignore` = node_modules/dist/.DS_Store/*.log；首次提交 `8cc9d4f`，235 文件）。之后每完成一段改造提交一次；**多 agent 并行前先 `git status` 看有没有别人未提交的改动**
- ⚠️ **同一工作区可能被多个 agent 同时改**：动手前后 `ls -lat src/**` 按时间戳核查归属，确认文件零重叠；别人动过 `storage.js` / `main.jsx` 这类共用文件后，**必须用最新源码重新 build + 复验自己那几条**
- ⚠️ **并行 agent 可能中途没 token 就停**：接手前先摸清半成品边界 —— 数据层做完没有？UI 做完没有？接进路由没有？别把「已完成」当「未完成」重做
- ⚠️ **`clipboard-images/` 是全局共享的**：看到新落盘的截图别默认是本项目的（曾把别的会话的微信文件列表当成用户新发的参考图）
- **规模红线（2026-09-16 已由用户放宽）**：原本是「不要再开店或加新菜」；用户现要求 **① 加 4 样食物（韩料重做 + 自创名咖啡 + 2 个面包，不新开店）② 全场统一改视觉风格**。其余仍守：**不再开新页目品类**、公益默认 30%、任何新机制先问「它是否让核心那件事更值得回来」
- **视觉红线（改造时不许破坏）**：禁 emoji；商品图走 `ItemArt`；手绘/实拍每款两张独立图；6 家店与四块磁贴的既有结构；「土」的机械原因是 **153 处硬编码色值 / 81 种颜色 vs 13 个变量** → 换风格前必须先做 token 收拢
