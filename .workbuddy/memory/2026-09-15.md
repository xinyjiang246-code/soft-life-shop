## 惜食柜（打折区）· 从零实现

**起因**：用户 09-14 说「我觉得还可以，每段时间出一些这种打折菜单」。方向上一轮已确认

始终没收到** —— 判断「这不是「继续等」，是「先做」」，按小铺现有视觉语言先实现，图来了再调。

**立意**：用户原话「这东西在商店里放很久了，别人不要的，我买下来就不算浪费粮食」。
→ 定位定成 **「关门前剩下的几份」，不是促销**。这条决定了后面几乎所有文案与配色。

1. **数据层**（`data.js`）：`RESCUE {perDay:3, tiers:[30,40,50], foodCounters, lines}` +
   `buildRescueShelf()` + `rescueLine()`；`rescueItems` 独立容器 + `setRescueItems/getRescueShelf`。
   - 折价品**独立 id**（`rescue-` 前缀 + `originalId`/`originalPrice`），**原商品价格绝不改写**
   - **不并进 `getAllItems()`** —— 否则会混进 `getItemsByCounter()`，店铺菜单里冒出打折品；
     只在 `getItem()` 里加一层查找（同世界菜单的做法）
   - 只从食物类柜台挑，选物店不参与
   - 单测（`tools/strip-assets.py` 把 webp 导入替换掉后可裸跑 node）：
     确定性 ✓ / 不污染店内菜单 ✓ / 原价未变 ✓

2. **踩坑：折率撞档**。初版三件各自独立哈希 → **三件全是 -50%**，看着像全场大促。
   → 改成按序轮转：先 `hashSeed(day+':rescue-tier')` 定 `offset`，再 `tiers[(offset+idx)%len]`。
   现在是 50/30/40，平均六折，像货架。

3. **持久化**（`storage.js`）：`KEY_RESCUE='soft-life-rescue-v1'` = `{servings, orders, yuan, records[]}`。
   **记账时机放在结局页**（送达才算数，和宠物成长 / 公益捐赠同一节拍），用 `rescuedRef` 挡
   re-render 二次记账。

4. **UI**：`RescueScreen.jsx` 新建；`HomeScreen` 加 `.rescue-strip` 细入口（店铺列表后、
   今日特调前）；`main.jsx` 加 `rescue` 路由 + `goBack` 分支；`CartScreen` 加原价划掉 +
   `cart-rescue-tag`；`EndingScreen` 加 `.rescue-recap`。

5. **踩坑：Cormorant 是旧式数字**。给小铺加惜食柜时发现 `1` 长得像 `I`、`3/4/5` 带长尾，
   价格和统计数字会读错（全站都有这个问题，不只是新页面）。加 `font-variant-numeric: lining-nums`。
   - **第一次尝试失败**：写在各自规则里怎么都不生效。查**压缩后**的 CSS 发现压缩器把
     `font:` 简写挪到了规则内部后面，而 `font:` 简写会把 `font-variant-numeric` 重置回 normal
   - **正解**：用 python 正则抓出 48 个「body 里同时含 Cormorant 和 `font:` 简写」的选择器，
     **合成一条规则追加到 `styles.css` 最末尾**
   - 教训：改完必须查 `dist/assets/index-*.css`，别只查源文件

**验证**：`scripts/flow-rescue.mjs` 全流程跑通 —— 首页入口条 → 柜子页 → 三件加购 → 购物袋 →
结算 → 配送 → 催单 → 结局（记账）→ 这本账。
