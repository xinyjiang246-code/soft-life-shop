## 两条 CDP 验收教训（写进 skill 了）
1. **React 受控输入不能直接赋 `.value`**：React 的 value tracker 会认为「值没变」而**吞掉 onChange**。
   必须 `Object.getOwnPropertyDescriptor(HTMLInputElement/HTMLTextAreaElement.prototype,'value').set.call(el, v)`
   再 `dispatchEvent(new Event('input',{bubbles:true}))`。
2. **无头 Chrome 里 `el.blur()` 不一定触发 React 的 `onBlur`**（元素没真聚焦时 `blur()` 是空操作）。
   React 18 的 `onBlur` 挂在根容器的原生 **`focusout`** 上 → 直接 `el.focus()` + 派发冒泡的
   `new FocusEvent('focusout',{bubbles:true})` 最稳。**症状很像「应用的保存功能坏了」，其实是验收脚本的锅。**

# 三补：冰淇淋红茶手绘图重画（用户：「冰淇凌应该是在上面的」）

## 用户报的问题
用户贴了店铺菜单里「冰淇淋红茶 / ICE CREAM BLACK TEA」那一行的截图。
放大后确认：**这幅是手绘（draw）那一面**（有吸管 + 米纸底），
**冰淇淋球被画在了杯子中间、沉在茶里** —— 而实拍（real）那一面从生成起就是对的
（球坐在杯口、盖在饮料上、奶浆流下来）。所以**只重画 draw，real 不动**。

## 做法（可复用的「单张重画」配方）
1. **image-to-image，两个参考各管一件事**：
   `image1 = 现在这张 draw`（管**画风**：蜡笔/色粉、米纸底、笔触），
   `image2 = 那张 real`（管**构图**：球必须在杯口上）。
   prompt 里把唯一的改动写死：「KEY CORRECTION — 球坐在杯口、高于杯沿，**不许沉在液体里**」。
2. 第一版就成了（球上去了）。但顺手生成的**第二版反而更糟**：

## 这轮新踩的坑（已补进 skill 第 51/52 条）
**「等动画播完」不能用 `getAnimations().map(a => a.finished)`** ——
首页乱走的猫、氛围条雨丝/星点、宠物呼吸圈都是 `iterations: Infinity`，
`a.finished` **永远不 resolve**，整条 await 挂到 CDP 20s 超时，报出来是
`Runtime.evaluate timed out` —— 看起来像页面卡死，其实只是等了一个永不结束的动画。
正解：只等 `effect.getTiming().iterations !== Infinity` 的那批 + `Promise.race` 兜 3s 上限。

**新工具 `tools/shot-page.mjs`**（≡ skill `scripts/shot-page.mjs`）：
`node tools/shot-page.mjs <url> <out.png> [clickSelector] [--scroll=N] [--wait=ms]`，
收尾打印 `STATE`（跑着的动画数 / 坏图 / **各容器实测底色·圆角·字色**）。
