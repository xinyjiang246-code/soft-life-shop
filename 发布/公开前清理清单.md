# 公开（GitHub）前的清理清单

## 先说结论

公开的代价只有一条：**推上去就撤不回来**（别人能 fork、能被爬）。所以要动的不是代码，
是「**哪些文件进仓库**」。产品本身不用改。

---

| 路径 | 问题 |
|---|---|

## 二、两条路，选一条

### A. 一个仓库，公开版只放该放的（省事）

用 `.gitignore` 挡住新文件 + `git rm --cached` 把已跟踪的**移出索引**（⚠️ 加 `--cached`，
文件留在本地，不会删）。

```bash
git rm -r --cached references 预览截图 .workbuddy/memory 发布
printf 'references/\n预览截图/\n.workbuddy/\n发布/\n' >> .gitignore
git commit -m "chore: 公开前把个人素材与过程记录移出仓库"
```

缺点：**历史里还留着**（第一次 commit 就带上去了），而且 `references/` 那 50MB 会一直压在
`.git` 里。想彻底干净只能重建历史。

### B. 两个仓库（最干净，推荐给「想当作品集」的情况）

- **私有仓库**放全部：含 references、截图、笔记，什么都不用动。
- **公开仓库**只放：`src/` `public/` `index.html` `vite.config.js` `package.json`
  `package-lock.json` `README.md` `tools/`（守卫脚本是这个产品的说明书，值得放）。

做法最省事的是**新开一个空目录、只拷该拷的**：

```bash
mkdir ../soft-life-public && cd ../soft-life-public
cp -R ../虚拟外卖模拟器/{src,public,tools} .
cp ../虚拟外卖模拟器/{index.html,vite.config.js,package.json,package-lock.json,README.md} .
git init && git add . && git commit -m "init: 慢活小铺"
```

⚠️ 拷完在**新目录**里跑一次 `npm install && npm run build`，确认脱离原目录也能跑起来。

## 三、依赖版本（本轮已修）

`package.json` 里原来全是 `"latest"` —— 别人 clone 下来哪天 `npm install` 就可能直接装不上
（React 20 一发版就崩）。现已钉成当时实际装上的版本：
`react ^19.2.8` · `react-dom ^19.2.8` · `vite ^8.2.2` · `@vitejs/plugin-react ^6.1.1` · `lucide-react ^1.40.0`。

`package-lock.json` 一直是有跟踪的，所以别人用 `npm ci` 装到的就是这一套。

---

## 四、GitHub Pages 怎么出 `dist/`

`dist/` 在 `.gitignore` 里（这是对的），所以 Pages **不能直接读它**。两条路：

- **用 GitHub Actions**：CI 里 `npm ci && npm run build`，再把 `dist/` 发到 Pages。（推荐，源码保持干净）
- 或者本地 `npm run build` 后，把 `published-site/` 推到 `gh-pages` 分支。

⚠️ `vite.config.js` 里的 `base: './'` **不要动** —— 正因为是相对路径，放在
`https://<你>.github.io/<repo>/` 这种子路径下资源才不会有 404。

---

## 五、还要决定一件事：许可

现在没有 `LICENSE` 文件，法律上等于**保留所有权利** —— 别人不能合法复用。
想要别人能玩能改，选一个：

- **MIT**：随便用、随便改，署个名就行。
- **CC BY-NC 4.0**：可以改，但不许商用。**对这个题材可能更贴** —— 免得有人拿去做成收费的「疗愈 App」。

选定后，把 `README.md` 末尾「尚未选定开源许可证」那段同步改掉。
